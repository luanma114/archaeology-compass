# Archaeology Compass v0.1.2 — prerelease

A V2 artwork update for **Minecraft 1.21.1 / NeoForge 21.1.235 / Java 21**.

## Changes since v0.1.1

- Adopted the balanced V2 copper compass artwork across all 32 frames: a subtle two-row copper side wall, one dark bottom edge, and softer shading between the face and shell.
- Updated the 400×400 project icon to match the V2 artwork.
- Synchronized the artwork generator, previews, documentation, and English/Chinese CurseForge page copy.
- Added an in-game mod list logo and completed the mod metadata: authors, issue tracker, homepage, and a fuller description.
- Target scanning, networking, crafting, configuration values, and needle-angle behavior are unchanged.

## Installation

Download the attached `archaeologycompass-0.1.2.jar` and place it in the instance's `mods` folder.

- Minecraft **1.21.1**
- NeoForge **21.1.235** minimum; any newer loader must also be compatible with Minecraft 1.21.1 and has not been separately verified.
- Java **21**
- Single-player: install on the client. Multiplayer: the server and all joining clients need the mod.
- This file is **NeoForge only**, not Forge or Fabric. JEI is optional, not required.

The compass finds nearby suspicious sand/gravel with remaining archaeology loot. It is not a long-range structure locator. Default search range is 64 blocks horizontally and 32 above/below, with an update every 20 game ticks. Searches only loaded chunks.

## Validation and known limitations

This is a **prerelease**, not a stable-release claim.

**Validated** in a development client on a newly created world:

- Crafting the compass, and the recipe unlocking in the recipe book.
- The needle pointing at the nearest valid target while the item sits in the inventory. A vanilla compass in the adjacent hotbar slot pointed a different way, which shows the needle tracks the archaeology target rather than a fixed frame.
- The Shift tooltip, including its "target found" state and the server's scan range.
- The V2 artwork in game.

**Not verified, and no claim is made about it:** installation from the release JAR in a clean instance, dedicated-server multiplayer, JEI display, and performance with large scan ranges or high player counts.

**Known limitations:**

- Ordinary target/inventory changes are reflected on the next scan, not instantly.
- Third-party targets must be in `archaeologycompass:archaeology_targets`, use `BrushableBlockEntity` or a subclass, and pass the loot-state checks. Arbitrary custom archaeology block entities are not supported.

Please [report issues](https://github.com/luanma114/archaeology-compass/issues) with Minecraft, NeoForge and mod versions, reproduction steps, and relevant logs with private information removed.
