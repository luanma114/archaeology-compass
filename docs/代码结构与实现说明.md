# 代码结构与实现说明

## 当前状态

当前仓库版本为 **0.1.1 预发布**。已实现物品注册、服务端扫描配置、目标方块标签、已加载区块方块实体扫描、按玩家缓存的目标状态、S2C 同步，以及客户端指针渲染（指向目标 / 无目标匀速旋转）。可考古有效性判定、合成配方与配方书解锁、创造模式标签页、中英文名称及 Shift 范围/搜索状态提示均已实现。外观为原创 32×32 铜制罗盘，包含 32 个角度帧。

目标版本：Minecraft `1.21.1`、NeoForge `21.1.235`、Java `21`。版本与元数据集中维护于 [gradle.properties](<../gradle.properties>)。

本文描述当前实现，不代表全部功能已完成游戏内验收。已有验证记录及待测项目见 [开发文档的验证状态](<NeoForge_MC模组开发文档.md#历史验证记录与当前待验项>)；本次采用 V2 后已完成资源一致性校验和离线构建，尚未重新进行游戏内验证。

## 模块职责

### `ExampleMod`

模组入口，由 `@Mod` 标记。

- 定义 Mod ID：`archaeologycompass`。
- 定义 `archaeology_targets` 方块标签键。
- 通过 `DeferredRegister` 注册 `archaeology_compass` 物品（`stacksTo(1)`）。
- 将物品加入原版“工具与实用物品”创造模式标签页。
- 注册服务端配置 `Config.SPEC`，并监听网络包注册事件。
- 在 `Dist.CLIENT` 分支向 Mod Bus 注册客户端设置监听（`ArchaeologyCompassClient.onClientSetup`）。
- 定义 `Target` 记录类型，保存目标维度和方块坐标。

`Target` 必须保存维度。仅保存坐标会使玩家换维度后错误指向同坐标位置。

### `Config`

服务端扫描配置：

| 配置键 | 默认值 | 作用 | 限制 |
| --- | ---: | --- | --- |
| `horizontalRadius` | 64 | X/Z 平面扫描半径 | 1–128 |
| `verticalRadius` | 32 | Y 轴扫描半径 | 1–64 |
| `scanIntervalTicks` | 20 | 周期扫描间隔（生命周期事件可额外更新） | 1–1200 |

配置由服务端决定。单人模式也存在集成服务端，因此同样按服务端配置运行。

### `ArchaeologyCompassEvents`

服务端 `PlayerTickEvent.Post` 监听器（`@EventBusSubscriber`，游戏事件总线）。

周期更新条件与行为：

1. 事件实体必须是 `ServerPlayer`；客户端不扫描。
2. 玩家 Tick 数到达 `scanIntervalTicks` 的整倍数（默认 `20` Tick）。
3. 玩家物品栏（含主手、副手）中存在罗盘时扫描；没有罗盘时清除旧目标和扫描初始化标记。

扫描由 `findNearestTarget` 在一次事件调用内完成：遍历已加载区块的方块实体，跳过未加载区块（`getChunkNow` 不触发加载）。先分别按 Y 轴垂直范围和 X/Z 平面水平距离筛选，再用 `isValidArchaeologyTarget` 判定有效性，最后用三维欧氏距离的平方保留最近坐标。垂直距离不占用水平半径。目前没有跨 Tick 分帧扫描或候选数量预算。

普通刷空、挖掘、超出范围或失去罗盘在下一次周期更新时反映，不是实时监听方块或物品栏变化。登录、换维度和重生事件会立即调用更新逻辑，不等待普通周期；重生事件中先清理旧缓存再更新，换维度后不复用旧维度目标。

有效性判定 `isValidArchaeologyTarget`：

- 方块必须属于 `archaeology_targets` 标签；
- 方块实体必须是 `BrushableBlockEntity`；
- 其 `saveWithoutMetadata` 结果含 `LootTable`（未刷扫）或 `item`（已首次刷扫、物品未完全刷出）键。二者都不存在时方块已刷空，不再定位。

注意 NBT 键是 `LootTable`（首字母大写），不是小写蛇形 `loot_table`。

扫描结果以玩家 UUID 为键保存到 `ArchaeologyCompassTargetState`。目标坐标或维度变化、旧目标被清除时，服务端向对应客户端发送 `ArchaeologyCompassTargetPayload`；通常不重复发送相同结果。`INITIALIZED_PLAYERS` 记录是否初始化过扫描状态，首次扫描无目标时也发送空目标包，让提示从“等待结果”切换为“未找到目标”。失去罗盘、换维度、重生和退出会处理初始化标记；退出时删除目标缓存。缓存只在服务器进程内使用，不写入存档。

### `ArchaeologyCompassTargetState`

服务端内存中的按玩家目标缓存。

- 使用玩家 UUID 作为键，不直接持有玩家对象。
- 仅保存维度和方块坐标组成的 `Target`。
- `set` 返回目标是否变化，供网络模块决定是否发送同步包。
- `clear` 返回清除前是否存在目标。
- 不保存到存档；登录时立即扫描重建，重生时清理旧值后重新更新。

### `ArchaeologyCompassTargetPayload` 与 `ArchaeologyCompassNetwork`

S2C 目标状态包。编码为：一个布尔表示是否存在目标，存在时写入维度资源 ID 和压缩方块坐标（`BlockPos.asLong()`）。仅允许 `playToClient` 方向。

`ArchaeologyCompassNetwork.sendTarget(player, target)` 向指定玩家发送目标（`null` 表示无目标）。

### `ArchaeologyCompassClientState`

客户端同步目标状态，无任何渲染 API 依赖，因此可被双端网络注册器安全引用。

- `target` 与 `receivedTarget` 均为 `volatile`，提供状态可见性；后者区分尚未收到首包与已确认无目标。
- `handleTargetPayload` 写入目标并标记已收到状态。
- `getTarget` 供客户端指针属性和提示事件读取，`hasReceivedTarget` 供提示判断是否仍在等待结果。
- `reset` 清空目标及接收标记，由客户端登出事件调用，防止状态跨连接残留。

### `client/ArchaeologyCompassClientEvents`

仅在物理客户端注册的游戏事件处理器：

- 登出时调用 `ArchaeologyCompassClientState.reset()`。
- 为罗盘添加中英文用途说明，按住 Shift 展示扫描规则和状态。
- 有玩家上下文且 `Config.SPEC.isLoaded()` 时，显示 NeoForge 同步的 SERVER 配置范围，不用客户端自定范围。
- 物品栏中没有罗盘时提示放入物品栏；否则根据是否收到首包、目标维度及是否存在目标显示等待、未找到或已找到状态。

### `client/ArchaeologyCompassClient`

客户端专属初始化（`Dist.CLIENT`），由 `ExampleMod` 在客户端分支监听 `FMLClientSetupEvent` 时调用。注册考古罗盘的 `minecraft:angle` 指针属性，绑定到 `ArchaeologyCompassPropertyFunction`。

### `client/ArchaeologyCompassPropertyFunction`

指针模型属性函数，实现 `ClampedItemPropertyFunction`。

- 从 `ArchaeologyCompassClientState` 读取服务端下发的目标。
- 同步目标存在、与显示实体同维度且实体不与目标中心重合时，按原版指南针指向逻辑计算角度（含朝向补偿与平滑插值）。客户端不重新检查目标的战利品状态。
- 无目标或未通过上述检查时，按游戏 Tick 匀速顺时针旋转：每 Tick 前进 `3/64` 圈，名义转速约为 `21.3` Tick 一圈；模型以 32 帧离散显示。
- 不读取物品上的 `LodestoneTracker` 组件，目标通过显式 S2C 网络包同步，不依赖罗盘物品的数据组件变更。

## 依赖与引用 API 说明

工程没有额外第三方运行时依赖。唯一开发依赖是 `net.neoforged:neoforge:21.1.235`，它同时引入 Minecraft `1.21.1` 的开发环境、NeoForge Loader、事件系统、注册系统和官方映射。Gradle 插件 `net.neoforged.gradle.userdev:7.1.38` 负责开发运行、重映射、资源处理和构建任务。

## 资源与数据格式

- [主模型](<../src/main/resources/assets/archaeologycompass/models/item/archaeology_compass.json>) 使用 `minecraft:item/generated`，并以 `minecraft:angle` overrides 选择本模组的 32 帧模型与原创贴图，不继承原版指南针模型。33 条 override 使用 32 个独立帧，首尾重复一帧用于角度接缝。
- [合成配方](<../src/main/resources/data/archaeologycompass/recipe/archaeology_compass.json>) 使用有序工作台配方：两把刷子、两个铜锭和一个指南针，产出一个罗盘。
- [配方书解锁](<../src/main/resources/data/archaeologycompass/advancement/recipes/tools/archaeology_compass.json>) 将获得刷子、获得指南针、已解锁配方三个条件按 OR 关系组合。配方可由 JEI 的标准工作台分类识别，无需专用插件或强制依赖；实际展示仍待验证。
- [资源生成脚本](<../generate_compass_assets.py>) 使用 Python 3 和 Pillow，生成贴图、帧模型、[全帧预览](<archaeology_compass_preview.png>)及[旋转预览](<archaeology_compass_rotation.gif>)。预览不是游戏截图。

| 文件 | 格式 | 目的 |
| --- | --- | --- |
| [模组元数据](<../src/main/resources/META-INF/neoforge.mods.toml>) | TOML | 声明 Mod ID、版本、许可证、描述和依赖范围 |
| [英文语言文件](<../src/main/resources/assets/archaeologycompass/lang/en_us.json>) / [中文语言文件](<../src/main/resources/assets/archaeologycompass/lang/zh_cn.json>) | JSON | 物品名称与用途、范围、状态提示本地化 |
| [罗盘主模型](<../src/main/resources/assets/archaeologycompass/models/item/archaeology_compass.json>) | JSON | 通过角度谓词选择 32 帧原创资源 |
| [目标方块标签](<../src/main/resources/data/archaeologycompass/tags/block/archaeology_targets.json>) | JSON 数据包标签 | 声明默认候选考古方块 |
| [罗盘合成配方](<../src/main/resources/data/archaeologycompass/recipe/archaeology_compass.json>) | JSON 配方 | 有序合成考古罗盘 |
| [配方解锁条件](<../src/main/resources/data/archaeologycompass/advancement/recipes/tools/archaeology_compass.json>) | JSON advancement | 获得刷子或指南针时解锁配方 |

## 当前限制与下一步

1. 尚未完成独立服务端与双客户端联机测试。
2. 扫描按方块实体一次性遍历，大量已加载区块或大量玩家时仍需 TPS 压力测试；分帧预算和区块索引是候选优化方案，目前未实现。
3. 正式贴图已采用 V2 折中铜壳（2 行侧壁、1 行暗色收边，透视比例 `0.64`）；游戏内显示效果仍需重新验证。模型几何厚度与方向映射未改。
4. 用户反馈上一轮 `0.1.1` 单人测试功能正常，但未逐项列出用例；Shift 提示、配方书解锁和 JEI 展示仍应按用例记录回归结果。没有自动化功能测试，构建通过不等于游戏交互验收通过。
5. 第三方标签方块若需被定位，必须使用原版 `BrushableBlockEntity` 并通过战利品状态判定；目前没有扩展的有效性判定接口。

## 构建与验证

```bat
gradlew.bat runClient
gradlew.bat runServer
gradlew.bat build
```

构建产物位于 `build/libs/`，当前默认主 JAR 名为 `archaeologycompass-0.1.1.jar`；配置见 [build.gradle](<../build.gradle>)。新增或修改实现、配置、资源后应执行完整构建，并在独立服务端验证没有客户端类加载错误；本次采用 V2 后已执行 `gradlew.bat build --offline`，并确认 JAR 内 32 帧贴图与批准候选完全一致；未重新启动客户端或完成 V2 游戏内验收。

[构建 CI](<../.github/workflows/build.yml>) 在 push / pull request 时使用 JDK 21 执行 `./gradlew build`，没有自动上传构建附件或创建 Release 的步骤。构建任务、资源校验和游戏内功能验收是不同验证层次，不能相互替代。
