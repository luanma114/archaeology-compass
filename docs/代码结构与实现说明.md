# 代码结构与实现说明

## 当前状态

当前工程是考古罗盘的可编译原型。已完成物品、配置、目标标签和服务端候选扫描。尚未完成指针渲染、目标缓存与同步、可疑方块刷空判定、分帧扫描和配方。

目标版本：Minecraft `1.21.1`、NeoForge `21.1.235`、Java `21`。

## 目录结构

```text
src/main/
├─ java/com/example/examplemod/
│  ├─ ExampleMod.java
│  ├─ Config.java
│  ├─ ArchaeologyCompassEvents.java
│  └─ ExampleModClient.java
└─ resources/
   ├─ META-INF/neoforge.mods.toml
   ├─ assets/archaeologycompass/lang/
   │  ├─ en_us.json
   │  └─ zh_cn.json
   └─ data/archaeologycompass/tags/blocks/
      └─ archaeology_targets.json
```

Java 包名仍为 MDK 初始值 `com.example.examplemod`。模组 ID 已固定为 `archaeologycompass`。发布前建议将包名迁移为正式组织域名，例如 `com.luanma114.archaeologycompass`；迁移时同时更新 Java 文件目录和 `gradle.properties` 的 `mod_group_id`。

## 模块职责

### `ExampleMod`

模组入口，由 `@Mod` 标记。

- 定义 Mod ID：`archaeologycompass`。
- 定义 `archaeology_targets` 方块标签键。
- 通过 `DeferredRegister` 注册 `archaeology_compass` 物品。
- 将物品加入原版“工具与实用物品”创造模式标签页。
- 注册服务端配置 `Config.SPEC`。
- 定义 `Target` 记录类型，保存目标维度和方块坐标。

`Target` 必须保存维度。仅保存坐标会使玩家换维度后错误指向同坐标位置。

### `Config`

服务端扫描配置：

| 配置键 | 默认值 | 作用 | 限制 |
| --- | ---: | --- | --- |
| `horizontalRadius` | 64 | X/Z 平面扫描半径 | 1–128 |
| `verticalRadius` | 32 | Y 轴扫描半径 | 1–64 |
| `scanIntervalTicks` | 20 | 两次扫描间隔 | 1–1200 |

配置由服务端决定。单人模式也存在集成服务端，因此同样按服务端配置运行。

### `ArchaeologyCompassEvents`

服务端 `PlayerTickEvent.Post` 监听器。

执行条件：

1. 事件实体必须是 `ServerPlayer`；客户端不扫描。
2. 玩家 Tick 数到达 `scanIntervalTicks` 的整倍数。
3. 玩家主手或副手持有考古罗盘。

满足条件后调用 `findNearestTarget`：

```text
遍历 X/Z 范围
  ↓
跳过未加载区块
  ↓
遍历 Y 范围
  ↓
判断方块是否存在于 archaeology_targets 标签
  ↓
用平方距离比较，保留最近坐标
```

`Level.hasChunkAt` 只允许读取已加载区块，避免罗盘扫描触发区块加载。

当前扫描结果只返回 `Target`，未写入任何状态。这是验证搜索规则的原型，不会让游戏内罗盘指针发生变化。

### `ExampleModClient`

客户端专属入口预留。未来职责：

- 注册 `1.21.1` 对应的物品模型属性；
- 接收服务端同步的目标位置或无目标状态；
- 以玩家位置、朝向与目标坐标计算指针角度；
- 无目标时生成连续旋转角度。

该类使用 `Dist.CLIENT` 限制。独立服务器不可引用任何客户端模型、渲染或 Minecraft 客户端类。

## 依赖与引用 API 说明

工程没有额外第三方运行时依赖。唯一开发依赖是 `net.neoforged:neoforge:21.1.235`，它同时引入 Minecraft `1.21.1` 的开发环境、NeoForge Loader、事件系统、注册系统和官方映射。Gradle 插件 `net.neoforged.gradle.userdev:7.1.38` 负责开发运行、重映射、资源处理和构建任务。

### Java 标准库

| 引用 | 用途 |
| --- | --- |
| `java.lang` | Java 自动导入；使用 `String`、`Double` 等基础类型。无显式第三方库。 |

### Minecraft API

| 包或类型 | 使用位置 | 目的 |
| --- | --- | --- |
| `net.minecraft.core.BlockPos` | `ExampleMod`、`ArchaeologyCompassEvents` | 保存方块坐标；`MutableBlockPos` 在扫描内层循环复用，减少对象创建。 |
| `net.minecraft.core.registries.Registries` | `ExampleMod` | 指定 `ARCHAEOLOGY_TARGETS` 是方块注册表中的标签。 |
| `net.minecraft.resources.ResourceKey` | `ExampleMod` | 为 `Target` 保存维度键，避免跨维度坐标混淆。 |
| `net.minecraft.resources.ResourceLocation` | `ExampleMod` | 创建 `archaeologycompass:archaeology_targets` 标识。 |
| `net.minecraft.tags.TagKey` | `ExampleMod` | 表示数据包定义的方块标签，支持整合包扩展候选目标。 |
| `net.minecraft.world.item.Item` | `ExampleMod` | 定义考古罗盘物品类型和物品属性。 |
| `net.minecraft.world.item.CreativeModeTabs` | `ExampleMod` | 获取原版“工具与实用物品”创造模式标签页键。 |
| `net.minecraft.world.level.Level` | `ExampleMod`、`ArchaeologyCompassEvents` | 读取维度、世界高度和方块状态；检查区块是否已加载。 |

| `net.minecraft.server.level.ServerPlayer` | `ArchaeologyCompassEvents` | 限制扫描只在服务端玩家运行，保证服务端为权威端。 |

### 资源与数据格式

| 文件 | 格式 | 目的 |
| --- | --- | --- |

## 数据与资源

### 目标方块标签

`data/archaeologycompass/tags/blocks/archaeology_targets.json` 默认含：

- `minecraft:suspicious_sand`
- `minecraft:suspicious_gravel`

整合包可通过数据包添加方块。标签表示“候选方块”，不自动表示该方块一定仍有考古战利品。

### 本地化

`assets/archaeologycompass/lang/en_us.json` 和 `zh_cn.json` 提供物品名称。新增物品、配置项、创造模式标签页名称时，必须同步添加两种语言键。

### 模组元数据

`META-INF/neoforge.mods.toml` 由 Gradle 从 `gradle.properties` 注入 Mod ID、版本和依赖范围。发布前检查名称、许可证、描述、作者和问题反馈链接。

## 当前限制与下一步

### 1. 可考古有效性判定

目前只检查方块标签。可疑沙子或可疑沙砾刷空后依旧是同一方块，不能继续被视为有效目标。

下一步：读取对应方块实体，确认仍存在可刷出的战利品；为第三方标签方块定义可扩展有效性接口或规则。

### 2. 性能

当前实现虽跳过未加载区块，但仍可能扫描大量方块。默认范围理论体积约为：

\[
(2 \times 64 + 1)^2 \times (2 \times 32 + 1) = 1,081,665
\]

实际只读取已加载部分，但多人或高频配置仍可能造成 TPS 下降。

下一步：使用单 Tick 工作预算将一次搜索拆分到多个 Tick，或在区块加载与方块变化事件中维护“候选目标索引”。只在完整扫描结束后更新最近目标，才能保证“最近”结论正确。

### 3. 状态与网络同步

扫描结果当前被丢弃。

下一步：为每个玩家维护目标状态，目标被刷空、挖掉、超范围或换维度时立即失效。服务端将目标或无目标状态同步给该玩家；客户端不直接决定游戏目标。

### 4. 模型和指针

Minecraft `1.21.1` 使用旧版物品模型 override 机制。考古罗盘需要 32 帧指针纹理或等效模型，并由客户端模型属性返回归一化角度。无目标状态返回持续变化值，使指针旋转。

模型注册和 JSON 必须严格按 `1.21.1` 实现；后续迁移更高版本时单独适配，不能直接复制。

### 5. 内容闭环

仍需添加：

- 物品模型和纹理；
- 合成配方；
- 指针目标同步；
- 单人、独立服务端、双客户端联机测试；
- 大范围和多人性能测试。
