# 代码结构与实现说明

## 当前状态

当前工程是考古罗盘的可运行原型。已完成：物品注册、服务端扫描配置、目标方块标签、基于已加载区块方块实体的服务端扫描、按玩家保存的目标缓存、仅在目标变化时进行的 S2C 同步，以及完整的客户端指针渲染（指向目标 / 无目标匀速旋转）。可考古有效性判定、合成配方、创造模式标签页、中英文本地化均已实现。

目标版本：Minecraft `1.21.1`、NeoForge `21.1.235`、Java `21`。

```text
│  ├─ Config.java                          服务端扫描配置

│  ├─ ArchaeologyCompassTargetPayload.java S2C 目标状态包与编解码
│  ├─ ArchaeologyCompassNetwork.java       网络包注册与发送

│  └─ client/
│     ├─ ArchaeologyCompassClient.java           注册 `minecraft:angle` 指针属性（Dist.CLIENT）
│     └─ ArchaeologyCompassPropertyFunction.java 计算指针角度（指向或匀速顺时针旋转）
└─ resources/
   ├─ META-INF/neoforge.mods.toml
   ├─ assets/archaeologycompass/
   │  ├─ lang/en_us.json
   │  ├─ lang/zh_cn.json
   │  └─ models/item/archaeology_compass.json  32 帧 `minecraft:angle` override 指针模型
   └─ data/archaeologycompass/
      ├─ recipe/archaeology_compass.json
      └─ tags/block/archaeology_targets.json
```

Java 包名和 `gradle.properties` 的 `mod_group_id` 均为正式值 `com.luanma114.archaeologycompass`。模组 ID 固定为 `archaeologycompass`。

注意：Minecraft `1.21` 起数据包目录改为单数——配方在 `recipe/`、方块标签在 `tags/block/`（不再是 `recipes/`、`tags/blocks/`）。

## 模块职责

### `ExampleMod`

模组入口，由 `@Mod` 标记。

- 定义 Mod ID：`archaeologycompass`。
- 定义 `archaeology_targets` 方块标签键。
- 通过 `DeferredRegister` 注册 `archaeology_compass` 物品（`stacksTo(1)`）。
- 将物品加入原版“工具与实用物品”创造模式标签页。
- 注册服务端配置 `Config.SPEC`。
- 在 `Dist.CLIENT` 分支向 Mod Bus 注册客户端设置监听（`ArchaeologyCompassClient.onClientSetup`）。
- 定义 `Target` 记录类型，保存目标维度和方块坐标。

`Target` 必须保存维度。仅保存坐标会使玩家换维度后错误指向同坐标位置。

### `Config`

服务端扫描配置：

| 配置键 | 默认值 | 作用 | 限制 |
| --- | ---: | --- | --- |
| `horizontalRadius` | 64 | X/Z 平面扫描半径 | 1–128 |
| `verticalRadius` | 32 | Y 轴扫描半径 | 1–64 |
| `scanIntervalTicks` | 20 | 两次扫描间隔 | 1–1200 |

配置由服务端决定。单人模式也存在集成服务端，因此同样按服务端配置运行。

### `ArchaeologyCompassEvents`

服务端 `PlayerTickEvent.Post` 监听器（`@EventBusSubscriber`，游戏事件总线）。

执行条件：

1. 事件实体必须是 `ServerPlayer`；客户端不扫描。
2. 玩家 Tick 数到达 `scanIntervalTicks` 的整倍数。
3. 玩家物品栏（含主手、副手）中存在考古罗盘。

满足条件后调用 `findNearestTarget`：遍历已加载区块的方块实体，跳过未加载区块（`getChunkNow` 不触发加载），用 `isValidArchaeologyTarget` 判定有效性，用平方距离保留最近坐标。

有效性判定 `isValidArchaeologyTarget`：

- 方块必须属于 `archaeology_targets` 标签；
- 方块实体必须是 `BrushableBlockEntity`；
- 其 `saveWithoutMetadata` 结果含 `LootTable`（未刷扫）或 `item`（已首次刷扫、物品未完全刷出）键。二者都不存在时方块已刷空，不再定位。

注意 NBT 键是 `LootTable`（首字母大写），不是小写蛇形 `loot_table`。

扫描结果以玩家 UUID 为键保存到 `ArchaeologyCompassTargetState`。玩家物品栏中没有罗盘或扫描未找到候选时清除旧目标。目标变化或清除时，服务端向对应客户端发送一次 `ArchaeologyCompassTargetPayload`。缓存仅存在于本次服务器运行期间，不写入存档。

### `ArchaeologyCompassTargetState`

服务端内存中的按玩家目标缓存。

- 使用玩家 UUID 作为键，不直接持有玩家对象。
- 仅保存维度和方块坐标组成的 `Target`。
- `set` 返回目标是否变化，供网络模块决定是否发送同步包。
- `clear` 返回清除前是否存在目标。
- 不保存到存档；重连或重启后由下一次扫描重新建立。

### `ArchaeologyCompassTargetPayload` 与 `ArchaeologyCompassNetwork`

S2C 目标状态包。编码为：一个布尔表示是否存在目标，存在时写入维度资源 ID 和压缩方块坐标（`BlockPos.asLong()`）。仅允许 `playToClient` 方向。

`ArchaeologyCompassNetwork.sendTarget(player, target)` 向指定玩家发送目标（`null` 表示无目标）。

### `ArchaeologyCompassClientState`

客户端同步目标状态，无任何渲染 API 依赖，因此可被双端网络注册器安全引用。

- `target` 字段为 `volatile`：网络包处理器可能在非渲染线程运行，而模型属性在渲染线程读取。
- `handleTargetPayload` 将 S2C 包中的目标写入本地状态。
- `getTarget` 供客户端指针模型属性读取。

### `client/ArchaeologyCompassClient`

客户端专属初始化（`Dist.CLIENT`），由 `ExampleMod` 在客户端分支监听 `FMLClientSetupEvent` 时调用。注册考古罗盘的 `minecraft:angle` 指针属性，绑定到 `ArchaeologyCompassPropertyFunction`。

### `client/ArchaeologyCompassPropertyFunction`

指针模型属性函数，实现 `ClampedItemPropertyFunction`。

- 从 `ArchaeologyCompassClientState` 读取服务端下发的目标。
- 目标有效（存在、同维度、不在脚下）时按原版指南针指向逻辑计算角度（含朝向补偿与平滑插值）。
- 无目标时返回随时间线性增长的匀速顺时针旋转角度（每 32/1.5 ≈ 21.3 Tick 转一圈）。
- 不读取物品上的 `LodestoneTracker` 组件——服务端修改物品组件后依赖库存同步，在结构方块等场景下同步不可靠；显式 S2C 网络包更可靠。

## 依赖与引用 API 说明

工程没有额外第三方运行时依赖。唯一开发依赖是 `net.neoforged:neoforge:21.1.235`，它同时引入 Minecraft `1.21.1` 的开发环境、NeoForge Loader、事件系统、注册系统和官方映射。Gradle 插件 `net.neoforged.gradle.userdev:7.1.38` 负责开发运行、重映射、资源处理和构建任务。

### Minecraft API

| 包或类型 | 使用位置 | 目的 |
| --- | --- | --- |
| `net.minecraft.core.BlockPos` | `ExampleMod`、`ArchaeologyCompassEvents`、`ArchaeologyCompassPropertyFunction` | 保存方块坐标；`asLong()` 压缩网络传输 |
| `net.minecraft.core.registries.Registries` | `ExampleMod` | 指定 `ARCHAEOLOGY_TARGETS` 是方块注册表中的标签 |
| `net.minecraft.resources.ResourceKey` | `ExampleMod` | 为 `Target` 保存维度键，避免跨维度坐标混淆 |
| `net.minecraft.resources.ResourceLocation` | `ExampleMod`、`ArchaeologyCompassTargetPayload` | 资源/标签标识与网络编解码 |
| `net.minecraft.tags.TagKey` | `ExampleMod` | 表示数据包定义的方块标签，支持整合包扩展候选目标 |
| `net.minecraft.world.item.Item` | `ExampleMod` | 定义考古罗盘物品类型 |
| `net.minecraft.world.item.CreativeModeTabs` | `ExampleMod` | 获取原版创造模式标签页键 |
| `net.minecraft.world.level.Level` | `ExampleMod`、`ArchaeologyCompassEvents` | 读取维度、方块状态 |
| `net.minecraft.server.level.ServerPlayer` / `ServerLevel` | `ArchaeologyCompassEvents` | 限制扫描只在服务端运行 |
| `net.minecraft.world.level.block.entity.BrushableBlockEntity` | `ArchaeologyCompassEvents` | 判定候选方块是否仍可考古 |
| `net.minecraft.client.renderer.item.ItemProperties` / `ClampedItemPropertyFunction` | `client/ArchaeologyCompassClient`、`client/ArchaeologyCompassPropertyFunction` | 注册与实现指针模型属性 |

## 当前限制与下一步

1. 尚未完成独立服务端与双客户端联机测试。
2. 扫描按方块实体一次性遍历，大量已加载区块或大量玩家时仍需 TPS 压力测试；必要时增加分帧预算或区块索引。
3. 当前使用原版指南针外观作为开发占位，可替换为自制模型纹理（需保留 `minecraft:angle` 属性注册）。
4. 第三方标签方块若需被定位，必须使用原版 `BrushableBlockEntity`；目前没有扩展的有效性判定接口。
